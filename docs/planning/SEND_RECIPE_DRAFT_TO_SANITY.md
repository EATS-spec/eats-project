# Send Recipe Draft To Sanity

## The Simple Idea

You give Codex one instruction, for example:

> Make an EATS recipe for ribollita and send it to Sanity as a draft.

After that, Codex handles the working steps:

1. Write the recipe.
2. Shape it for the EATS Sanity recipe schema.
3. Generate or choose the needed recipe images.
4. Save the image files when Codex generated them.
5. Run checks.
6. Send the recipe and generated images to Sanity as a draft.
7. Return the Sanity draft link and review notes.

You should not need to think about JSON, scripts, local files, or command flags.
Codex may use helper commands behind the scenes, but the request should still
feel like asking for a recipe.

## What Sanity Does

Sanity stores the draft. It is where you review, adjust media, preview, organize,
and publish.

Sanity is not the default place where recipes are invented.

Sanity can also hold rough recipe ideas. Use the Recipe Idea Queue for concepts
that are interesting but not ready for Codex to draft yet.

## What Codex Does

Codex is the workshop. It creates the content, prepares the media pack, checks the
draft, and sends it to Sanity.

If you are working in a Codex thread, Codex can also help generate the recipe
images as part of that thread workflow, subject to the image limits on your
ChatGPT/Codex plan. Those images are then saved locally and attached to the
Sanity draft.

That is different from asking a background script to generate images while no
Codex thread is involved. Fully unattended script-based image generation would
need an API key and would be billed separately from a ChatGPT subscription.

## The Command Codex Uses

If Codex is starting a brand-new recipe from a dish name, it can first create a
consistent working file and image folder:

```bash
npm run recipes:start -- --title "Ribollita"
```

When the recipe is ready, Codex runs:

```bash
npm run recipes:draft -- --input scripts/automations/payloads/my-recipe.json
```

For a no-write check first, Codex can run:

```bash
npm run recipes:draft:dry-run -- --input scripts/automations/payloads/my-recipe.json
```

These commands are for Codex. The user-facing request should stay natural:

> Make this recipe and send it to Sanity as a draft.

In normal use, you should not need to type either command yourself. They exist
so Codex has a dependable way to move finished work into Sanity.

After a draft is created, the report includes a local Studio proof URL. Codex can
also open that draft in Google Chrome with:

```bash
npm run recipes:draft -- --input scripts/automations/payloads/my-recipe.json --open-chrome
```

That browser step is optional. It is proof that the draft opened in Studio; it is
not a required publishing step.

## Idea Queue

Use the Recipe Idea Queue when a dish idea is not ready for a full draft yet:

1. Add the dish name.
2. Add the useful angle, constraints, or season.
3. Add media ideas if the recipe will need specific visuals.
4. Set the status to **Ready for Codex draft** when the idea has enough shape.

Codex can inspect ready ideas with:

```bash
npm run recipes:ideas
```

Then Codex can turn one of those ideas into a normal Sanity recipe draft.

## Draft Review Checklist

Recipe Manager now includes a Draft Review Checklist:

1. **Missing essentials**: title, slug, description, categories, ingredients, or steps.
2. **Missing media**: hero image, alt text, gallery alt text, or step-image alt text.
3. **Ready for final review**: enough structure and media for human review.

## Images

If Codex generates images, the recipe payload can include a main image, gallery
images, and step images:

```json
{
  "imageSource": {
    "filePath": "output/generated-images/ribollita.png",
    "filename": "ribollita.png",
    "credit": "Generated by Codex for EATS"
  },
  "gallery": [
    {
      "filePath": "output/generated-images/ribollita-process.png",
      "filename": "ribollita-process.png",
      "alt": "Vegetables simmering in a pot for ribollita",
      "caption": "Cook the soffritto until sweet before adding beans and greens.",
      "credit": "Generated by Codex for EATS"
    }
  ],
  "steps": [
    {
      "instruction": "Simmer the soup until the greens are tender.",
      "imageSource": {
        "filePath": "output/generated-images/ribollita-step-simmer.png",
        "filename": "ribollita-step-simmer.png",
        "alt": "Ribollita simmering with greens and beans",
        "caption": "The broth should look hearty, not thin.",
        "credit": "Generated by Codex for EATS"
      }
    }
  ]
}
```

When `recipes:draft` sees local generated image files, it uploads them to
Sanity with the draft.

Remote image URLs are still review-first unless explicitly uploaded.

The draft report also includes media-quality notes so Codex can catch weak image
coverage, thin alt text, or missing captions before the recipe is published.

The preferred no-extra-Sanity-cost path is:

1. Ask Codex for the recipe.
2. Let Codex create the useful recipe images in the thread.
3. Let Codex save those image files and include their paths in the recipe.
4. Let `recipes:draft` upload them to Sanity with the draft.

## Default Media Pack

When the user does not give image instructions, Codex should make a compact
recipe media pack:

1. **Main image**: finished dish, useful as the recipe hero.
2. **Gallery image**: one process, ingredient, or serving detail image.
3. **Step image**: one instructional image only when it makes a cooking step
   clearer.

Do not generate filler images just to hit a quota. A recipe with no visual
technique moment can use only the main image and one gallery image.

## Cost Boundary

The default workflow does not invoke Sanity AI Assist, Content Agent, or Agent
Actions. AI work happens in Codex or another external tool already available to
the workflow.

For this EATS workflow, treat image generation this way:

- **Codex thread image generation**: preferred. This uses Codex/ChatGPT plan
  limits and avoids separate Sanity AI costs.
- **Local script image generation**: optional. This is only for fully unattended
  automation and requires `OPENAI_API_KEY`, which is billed separately from a
  ChatGPT subscription.
- **Sanity AI features**: not part of the default recipe workflow.
